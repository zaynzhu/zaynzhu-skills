## 判断矩阵

| 现状 | 默认处理 |
|------|----------|
| 两份都没有 | 新建两个文件，写入相同受管区块 |
| 只有一份 | 保留现有文件内容，新建另一份；共享区块保持一致 |
| 两份都有且无受管区块 | 分析共享与专属内容，预览后引入受管区块 |
| 任一文件已有受管区块 | 只替换受管区块内部 |
| 受管区块缺失结束标记或重复出现 | 停止自动写入，报告结构损坏并请求确认 |

只修改根目录的两份规则文件。嵌套 `AGENTS.md`、`CLAUDE.md` 和其他 AI 规则只作证据。

## 内容分类

把现有内容分为：

1. **共享工程规则**：技术栈、命令、测试、目录、通用编码约定。
2. **平台专属规则**：只适用于 Claude Code、Codex 或某个工具的行为。
3. **自定义内容**：团队说明、历史背景、人工维护的特殊 section。
4. **受管内容**：位于 `project-onboard` 标记之间的内容。

共享规则可以进入受管区块；平台专属和自定义内容保留在区块外。不要为了让两份文件逐行一致而复制或删除平台专属内容。

## 受管区块

共享内容使用唯一的一对标记：

```markdown
<!-- project-onboard:begin -->
<!-- 此区块由 project-onboard 维护；区块外可保留平台专属规则 -->

...

<!-- project-onboard:end -->
```

规则：

- 每份文件最多一个受管区块。
- 两份文件的受管区块逐行一致。
- 更新时只替换 begin/end 之间的内容。
- 不移动、格式化或清理区块外内容。
- 新文件可在区块前添加简短一级标题；一级标题不属于共享一致性检查。

首次遇到没有标记的现有文件时：

- 默认模式：展示哪些现有 section 将被纳入受管区块，确认后移动；原有措辞尽量保留。
- 快路模式：只自动纳入两份文件中一致且没有证据冲突的共享内容；其他内容留在区块外。
- 不要简单追加同名 section，避免重复标题。

## 证据冲突

不要使用“现有规则永远优先”或“配置永远优先”的固定排序。

| 情况 | 处理 |
|------|------|
| 用户本轮明确确认 | 采用用户确认，并记录来源 |
| 现有规则与强事实一致 | 纳入共享区块 |
| 现有规则与 manifest/CI/lockfile 冲突 | 展示冲突，等待裁决 |
| 两份现有规则互相冲突 | 保留在各自区块外，等待裁决 |
| 只有 README 或 git log 线索 | 标为弱证据，不生成强制规则 |

快路模式遇到未解决冲突时，保留现有内容，不在共享区块新增相互矛盾的规则，并在交付报告列出。

## 脏工作区

使用只读 `git status --short` 识别未提交改动：

- 无关文件有改动：继续，但不修改、不暂存、不提交它们。
- 目标规则文件有改动：采用最小区块合并，写入前保存并展示 diff。
- 用户要求整份重写且目标文件有未提交改动：必须再次获得明确确认。
- 无法使用 git：按普通现有文件处理，不把它当作错误。

## 合并与重写

### 合并（默认）

- 保留区块外全部内容。
- 更新或创建受管区块。
- 只把已确认的共享规则写进受管区块。
- 两份文件的受管区块相同，文件整体可以不同。

### 整份重写

只有用户明确说“整份重写”“替换现有规则”“旧文件全部不要”时执行：

- 仍保留证据账本和冲突检查。
- 写入前展示整文件 diff。
- 目标文件有未提交改动时再次确认。
- 不把一份文件的平台专属内容机械复制到另一份。

## 快路模式

用户说“直接生成”“不用确认”“快速”时：

- 跳过合并选择和证据确认。
- 不跳过现有文件读取、受管区块识别、冲突分析或自审。
- 默认合并，不整份重写。
- 保留所有区块外内容。
- 未解决冲突不进入受管区块。

## 幂等性检查

写入后用相同证据重新生成一次草稿：

1. 受管区块内容应与磁盘一致。
2. 区块外内容应逐字保持。
3. 第二次拟议 diff 应为空。

若第二次仍产生 diff，修正规则顺序、空行、标题或合并逻辑后再交付。
