# 已有文件合并 / 重写规则

`project-onboard` 处理项目里已存在 `CLAUDE.md` 或 `AGENTS.md` 的情况。**绝不直接覆盖**——用户写过的内容优先级高于从配置推断的，要尊重。

## 判断矩阵

| 现状 | 处理 |
|------|------|
| 两份都没有 | 主场景，直接生成，跳过本文件 |
| 只有 `CLAUDE.md` | 读它作证据 → 生成增强版 → 同步写到两份（`CLAUDE.md` 按合并/重写处理，`AGENTS.md` 新建） |
| 只有 `AGENTS.md` | 同上，对称处理 |
| 两份都有 | 读两份作证据 → 生成增强版 → 两份都按合并/重写处理 |

## 现有内容作为证据

读现有 `CLAUDE.md`/`AGENTS.md` 时，把里面的规则当作**高优先级证据**填进账本：

- 用户手写的规则 > 从配置推断的规则。冲突时以用户写的为准，并在账本标注"来自现有 CLAUDE.md"
- 现有文件里的 section 即使内容粗，也覆盖了"用户认为该写啥"的意图，是 section 覆盖度的参考

例如：现有 `CLAUDE.md` 写了"用 pnpm 不用 npm"，而 `package.json` 没指明包管理器——以用户的为准，账本里开发命令标 pnpm，证据来源记"现有 CLAUDE.md"。

## 合并（默认）

保留用户已有的所有内容，只**补上缺失的 section**。顺序按 11 个固定 section 排列——用户已有的内容归位到对应 section，缺失的补上。

```
现有文件 section: [项目定位, 技术栈, 开发命令, 提交规范]   （4 个，粗）
生成增强版:       [项目定位, 技术栈, 目录结构, 开发命令,  ← 目录结构新增
                  测试, 代码约定, 提交规范, 目录约定,     ← 测试/代码约定/目录约定新增
                  环境变量, 关键入口, 给agent的工作指引]  ← 全新增
```

合并时：
- 用户已有 section 的内容**原样保留**，除非有明显错误（如命令写错）——错误才提示用户改，不擅自改
- 新增 section 从证据账本提炼
- 重新按 11 section 顺序排列，可能需要移动用户原有内容的位置

## 整份重写

用户明确选"重写"时，以新内容替换整份。仍基于证据账本，但不再保留用户原有措辞。适用场景：用户说现有文件太旧/太烂/完全重新来。

## 快路模式

用户说"直接生成""不用确认""快速"时：
- 跳过上面的选择询问，**默认合并**
- 已有文件仍读作证据（这步不能跳，否则会丢用户意图）
- 扫完直接生成 + 自审 + 写入

## 其他 AI 规则文件

扫到 `.cursorrules` / `.windsurfrules` / `.coderc` / `.aider*` 等：
- **读**：作扫描线索吸收进账本（这些文件里的规则也是"用户已表达意图"）
- **不动**：不修改、不删除这些文件，这个 skill 只产出 `CLAUDE.md` 和 `AGENTS.md` 两个文件
- 在证据账本里标注"来自 .cursorrules"等来源
