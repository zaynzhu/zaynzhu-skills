# 事实核查 — Fact-Check

## 设计理念

先厘清这个技能要防的是什么。AI 有幻觉，现在少了但还有；**而人类的幻觉往往比 AI 还大**——有句话叫"AI 帮很多人走上了愚昧之巅"。一个自信的说法，无论是 AI 还是人说的，背后常常是：事实微妙地错了/脱离了上下文，或者事实全对但结论根本推不出来。

所以这个技能的底色是**笛卡尔式的怀疑**：对任何说法先怀疑，再按"证据 + 推理"决定相信到什么程度。但"怀疑一切"不等于"否定一切"——它不判对错，而是给一个**校准过的置信度**：在什么条件下可相信、能信几分。

核心信念：**核查 ≠ 判对错。核查 = 把一团混在一起的说法，拆成可验的事实、推出的结论、主观的价值判断，分别验其真假与推理，最后告诉你能信到什么程度。**

关键洞察：大多数"幻觉"不是凭空捏造，而是两种——
1. **事实层**：事实微妙地错、或真但被夸大/脱离上下文（"增长 50%"只在某段某群体成立，被说成普遍规律）
2. **推理层**：事实全对，但结论推不出来（藏着没验证的假设、把相关当因果、漏了其他解释）

所以本技能攻两层：先验事实真假，再**假设事实全对**，单独审推理是否成立。第二层是人类的幻觉重灾区——人会拿一串真事实拼出假结论。

## 工作流程

### 准备：锁定说法

从用户输入锁定**要核查的说法**（观点/结论/数据/方案）。

- 用户没给说法：问一句"核查哪个说法？贴出来"。
- 说法很模糊（如"AI 很厉害"）：不反问，用最合理的具体理解开始，在拆解开头点明你理解的说法是什么。
- 说法是一段长文：先提炼出其中最核心的几个可核查命题，不要被修辞带跑。

### 第一步：拆成三层

把说法拆开，**分开标注**——混在一起没法核查，因为三类东西核查方式完全不同：

- **可外部验证的事实**：有客观真假的陈述（"X 公司去年营收 10 亿"）。→ 进第二步联网核查。
- **从事实推出的结论**：由事实推出的判断（"所以 X 是行业第一"）。→ 进第三步推理链检查。
- **价值判断**：好/坏、应该/不应该的主观评价（"所以 X 是成功的"）。→ 不核查真假，只识别出来并指出它基于什么价值标准。

为什么这么拆：价值判断没有"真假"，只有"基于什么标准"；硬去"核查"一个价值判断是范畴错误。识别出来、说明它的标准，就够了。事实才能验真假。结论要单独看推理。

如果核查对象是**方案**：方案的"事实"=它的前提（"市场有 X 需求""技术能做 Y"），"结论"="这方案会 work"，"价值"=它的优先级取舍。同一框架套用。

### 第二步：事实核查（联网为主，无网降级）

对每个事实，联网核查四要素：**来源、样本、时间、完整上下文**。逐条标 5 级。**优先用 `enhanced-tavily-search` skill**（结构化检索 + 带来源摘要，可按时间/域名筛选，正好适配核查需要的来源和日期），再辅以 WebSearch/WebFetch 和 arXiv。

**5 级标记**（不是非黑即白，"基本成立需收窄"是最常见也最有用的）：

1. **已证实**：多个独立可靠来源一致支持，来源一手、样本充分、时间对得上、上下文完整。
2. **基本成立，但需要收窄**：核心为真，但范围/程度/时间被夸大。如"增长 50%"只在某段某群体成立，说法泛化了。→ 给出应收窄到的具体范围。
3. **存在争议**：有可靠反证或来源分歧，不能简单判真。→ 并列呈现各方说法 + 来源。
4. **证据不足**：找不到足够证据支撑，但也无明确反证。→ 不要默认它假，标"证据不足"。
5. **明显错误**：可靠来源直接反驳。→ 给出反证。

**核查纪律**：
- 一手来源优先（官方/原始数据/论文 > 权威原创报道 > 转载聚合）。多个媒体引用同一错误会造成"循环印证"假象，追到原始来源。
- 数据类必查：谁统计的、样本多大、什么时间、什么口径。同一数字在不同口径下意义完全不同。
- 学术/技术类查 arXiv / 原始论文，别信二手转述。
- 冲突信息并列呈现，不悄悄选一个。
- 搜不到的明确标"证据不足"或"未能核实"，绝不拿模型记忆充数、绝不编造。

**无网降级**：没有联网工具时，事实部分**全部标"未能联网核实"**，但**不中断**——继续做第三步推理链检查（它不依赖外部），并在输出开头明确声明"事实未联网核实，以下推理分析基于假设事实成立"。把能做的推理价值给到用户，而不是因为没网就整个罢工。

### 第三步：推理链检查（假设事实成立）

**关键：这一步假设第二步的事实全部成立**，单独审"从事实到结论"这一跳。因为即使每条事实都真，结论也可能推不出来。这是人类幻觉的重灾区。

逐项检查：

1. **事实能否推出结论**：即便事实全真，结论是逻辑必然、合理推断、还是跳跃？很多说法的事实和结论之间根本没有逻辑桥。
2. **藏没藏未经验证的假设**：结论依赖了哪些没说出口的前提？这些前提本身成立吗？（"X 增长快 → 值得投"——藏着"增长会持续""增长能转化成回报"两个没验证的假设。）
3. **是否混淆相关与因果**：A 和 B 同时出现/相关，就被说成 A 导致 B。这是最常见的推理谬误。相关≠因果，要问有没有反向因果、第三方共因、或纯巧合。
4. **是否遗漏其他解释或关键信息**：有没有同样能解释这些事实的替代说法被忽略？有没有一个能翻转结论的关键信息没提？
5. **结论在什么条件下成立或失效**：给出结论的边界——什么条件下它成立，什么条件下它崩。没有无条件成立的结论。

### 第四步：输出四件套

1. **哪些事实可信，哪些需要修正**：逐条带 5 级标记 + 需修正的给出修正后的具体说法。
2. **推理链中最关键的漏洞**：1-2 个最致命的，不是罗列所有小毛病。指出它在哪一跳、为什么是漏洞。
3. **补强后的最合理版本**：把原说法改写成证据和推理都站得住的版本。不是"原说法错了"就完事——给出一个你愿意为之负责的、最站得住的重述。
4. **目前可以相信到什么程度**：**条件式校准**，不是"基本可信"这种空话。格式："在 X 条件成立时可相信 Y；若 X 不成立，只能信 Z / 不可信。" 给出能信几分、信的前提、不信的触发条件。

## 边界说明

**不要做的事：**
- 不要把价值判断当事实去"核查真假"——那是范畴错误，识别出它的标准即可。
- 不要非黑即白地判对错。5 级标记里"基本成立需收窄"和"存在争议"才是最常见的，别为了干脆硬归到"已证实"或"明显错误"。
- 不要在没联网时拿模型记忆当核查结果——标"未能联网核实"，别编造、别拿可能错的知识核查可能错的说法（那违背笛卡尔底色）。
- 不要跳过第三步。事实全对但结论推不出来，是人类幻觉的最大来源——只验事实不验推理，等于只做了一半。
- 不要把"推理链漏洞"罗列成流水账。只挑 1-2 个最关键的，多了每个都不致命。
- 不要给"基本可信"这种没校准的置信度。必须带条件："在 X 条件下可相信 Y，否则不可信"。

**要做的事：**
- 拆解先做，且三层分开标——这是后面一切的基础。
- 事实核查四要素（来源/样本/时间/上下文）都要查，数据类尤其要查口径。
- 推理链检查要"假设事实成立"再做——单独审那一跳，别和事实真假混在一起。
- 补强后版本要你愿意为之负责，不是和稀泥的折中。
- 置信度要校准到"信几分 + 信的前提 + 不信的触发条件"。

## 力度控制

**默认行为**：全流程，5 级标记 + 推理 5 项 + 四件套做全，最大怀疑。

用户可在请求中调整：
- `--quick`：只核最关键的 2-3 个事实 + 推理最关键 1 个漏洞 + 置信度，跳过其余（适合快速过一遍）。
- `--deep`：每个事实展开来源比对，推理每项详写（适合重要决策前的严格核查）。
- 用户直接描述（如"快速查一下"、"这个很重要要严查"）同样生效。

## 与其他技能的区分

- **adversarial-review**：红队批判，找致命弱点。本技能是**验真假 + 验推理**，不是找弱点——同一个说法，adversarial 问"哪里会垮"，本技能问"能信几分"。
- **steel-man**：已有立场要正反论证后做决定。本技能不论证正反，只核查一个说法的依据和推理。
- **enhanced-hv-analysis**：系统研究一个对象的发展史+竞争格局，出长报告。本技能是**单点核查一个说法**，不出研究报告。
- **dual-layer-explanation**：讲懂一个概念。本技能不解释概念，核查说法真伪。
- 当用户要的是"批判找弱点" → adversarial-review；"正反论证做决定" → steel-man；"系统研究出报告" → enhanced-hv-analysis；"讲懂概念" → dual-layer-explanation；"这个说法能信几分" → 本技能。
