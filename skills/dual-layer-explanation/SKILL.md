# 双层解释法 — Dual-Layer Explanation

## 设计理念

很多人跟 AI 说"把我当小学生解释"，或者我自己爱用的"我是一个学习能力很强的智障"。这确实容易听懂——但很容易停在"好像懂了"的阶段：**类比记住了，真正的机制还是一团雾。**

为什么会这样？因为单层的小白解释只给了一个**直觉钩子**，没给机制本身。你记住了"RAG 就像开卷考试"，但开卷考试的哪一部分对应 RAG 的哪一步？什么时候开卷考试这个类比会失效？你都说不清。直觉有了，却接不上机制——这就是"好像懂了"的来源。

本技能的解法：**解释两遍，再搭桥。**

- **小白版**给你一个能挂住直觉的钩子（生活化语言 + 具体例子）
- **专业版**给你机制本身（准确术语 + 核心机制 + 适用边界 + 常见误解）
- **三件套**把两层连起来，并主动拆掉"好像懂了"的陷阱

核心信念：**听懂类比 ≠ 理解机制。** 只有当你能把类比里的每一部分映射回机制的对应部分，并且知道类比在哪里失效，才算真懂。

## 工作流程

### 准备

从用户输入中提取要解释的**概念或问题**。用户可能用模板（"我想学习的是：【X】"），也可能直接说"解释一下 X"、"什么是 X"。无论哪种形式，锁定那个 X 即可。

**两种情况要分开处理**：
- 用户没给 X（只说"双层解释一下"却没带概念）：这时确实得反问一句"想学哪个概念？"——因为没有任何输入根本无法开始，这和下面"X 模糊"不同。
- 用户给了 X 但 X 模糊——**看模糊程度**：轻微模糊（比如"解释一下 AI"→收窄到"AI 的基本原理"）不要反问，先在心里把 X 收窄到一个可解释的具体层面，在小白版开头点明你理解的 X 是什么，然后直接开始；严重模糊（用户啥都没说清、或方向完全定不了）才反问一句确认。学习型技能最忌讳把"搞清楚问什么"的活推回给用户，但也别在严重模糊时硬答错对象。

### 第一层：小白版

**要求**：用生活化的语言 + 一个具体例子，让完全没有基础的人也能听懂。

**为什么这么要求**：纯专业术语会把零基础的人挡在门外，他需要一个能挂住直觉的钩子才能往下走。

**怎么做才合格**：
- 例子必须**具体到这个概念**，不是随便一个类比糊弄。坏例子："闭包就像一个盒子"——任何东西都可以是盒子，没说清机制。好例子：把闭包讲成"一个函数随身带了个私人笔记本，函数走了笔记本还在"——这个例子的每个部分都能映射回闭包的机制。
- 例子要能**走完一遍流程**，而不只是打个比方。让读者跟着例子走一遍，看到概念在其中怎么起作用。
- 不要在小白版里偷偷塞专业术语。要塞，就只用大白话说现象，术语留给第二层。

### 第二层：专业版

**要求**：用准确术语讲清四件事——核心机制、适用边界、常见误解。

**为什么是这四件**：
- **核心机制**：补上小白版没给的"它到底怎么运作的"。这是从"好像懂了"到"真懂"的关键一步。
- **适用边界**：说清它在什么条件下管用、什么条件下不管用。不知道边界，就没法正确使用。
- **常见误解**：直接点出大家最容易搞错的地方——这往往就是"好像懂了"的具体出处。主动把雷排掉，比让用户踩了再纠强。

**怎么做才合格**：
- 术语要准确，但每个术语出现时都要在上下文里能被理解（可以呼应小白版的例子，但不能再只用例子）。
- 常见误解要具体——"有人以为 X 其实是 Y，但实际是 Z"，而不是泛泛说"容易搞混"。

### 收尾三件套

两层讲完，还要做三件事把它们连起来、并验证理解。**这三件套是本技能的灵魂**——没有它们，两层就是两个孤岛，用户照样停在"好像懂了"。

#### 1. 小白说法 ↔ 专业术语 对应关系

把小白版里用到的每个生活化说法，和专业版里的术语一一对应。

**为什么**：这是两层之间的桥。没有桥，你记住了类比，却不知道类比的哪一部分对应机制的哪一部分。有了桥，你能用直觉反推机制——这是"真懂"的标志。

**怎么做**：用一个对照表，左列小白说法，右列对应的专业术语，必要时加一句"对应的是机制的哪一步"。

#### 2. 我最容易理解错的地方

主动指出：类比在哪里失效？机制在哪里反直觉？用户最可能踩哪个雷？

**为什么**：每个类比都有失效点。不点出来，用户会把类比当机制，在类比不成立的地方继续套用——这正是"好像懂了"的根源。主动点名失效点，等于提前给用户装了个防错雷达。

**怎么做**：说清"小白版里 X 的比喻，在 ___ 这一点上不成立，因为机制实际上是 ___"。要具体到失效的那一点，不要笼统说"类比有局限"。

#### 3. 3 个检查问题

出 3 个问题，让用户检验自己是否真正理解。

**为什么**：被动读"好像懂了"，主动答才能验证。好问题逼你用机制推理，而不是认出原话——能答对说明机制进了脑子，答不对说明还停在类比层。

**什么样的问题才是好问题**（重要）：
- **测迁移，不测复述**：换个场景让你用机制推一遍，而不是问"小白版里那个例子是什么"。
- **测边界，不测定义**：给一个边界条件问"这种情况还管用吗，为什么"，而不是问"X 的定义是什么"。
- **测误解，不测背诵**：故意抛出常见误解里的错误说法，问你它错在哪，而不是问"正确说法是什么"。

3 个问题各覆盖一种类型（迁移 / 边界 / 误解），不要三个都同一种。

## 边界说明

**不要做的事：**
- 不要只讲小白版就收工——那是用户本来就会的"把我当小学生"，本技能的价值在第二层和三件套。
- 不要用万能类比糊弄（"X 就像一个盒子/一个工具"）。例子必须具体到概念、能映射机制。
- 不要在三件套的对应关系里只列术语不对应机制——桥的价值在于"类比的哪部分 = 机制的哪步"，不是翻译词汇。
- 不要出复述型/定义型的检查问题。"X 是什么"测不出真懂，要测迁移、边界、误解。
- 不要把常见误解写成"容易混淆"这种空话。要具体到"有人以为 A，其实 B，因为 C"。

**要做的事：**
- 小白版的例子要能让零基础的人跟着走一遍，看到概念怎么起作用。
- 专业版的常见误解要主动排雷——这是把"好像懂了"变成"真懂"的最有效手段。
- 对应关系表是两层之间的桥，每行都要能回答"这部分对应机制的哪一步"。
- 检查问题要让用户必须动用机制推理才能答，而不是靠回忆类比蒙混。
- 收尾主动邀请用户答 3 个问题并回发——把被动学习变成主动验证。

## 力度控制

**默认行为**：两层都讲足，三件套做全，适合真正想搞懂的学习场景。

用户可在请求中调整：
- `--quick`：压缩篇幅，小白版一句话例子 + 专业版要点 + 三件套精简（适合快速过一遍、不是深学）。
- `--deep`：专业版再加一层深度，适用边界和常见误解各展开（适合备考/硬核学习）。
- 用户直接描述（如"快速过一下"、"我要考试要深一点"）同样生效。

## 与其他技能的区分

- **socratic-questioning**：用户说不清自己想问什么，靠追问收敛出真问题。本技能是用户**已经知道想学什么**，要把一个概念讲透。
- **first-principles**：把问题还原到底层公理重新推导方案。本技能不还原公理，而是**分两层把现有概念讲明白**。
- **steel-man**：已有立场要正反论证后决定。本技能不是论证/决策，是**学习理解**。
- 当用户要的是"我有点乱帮我理清问题" → socratic-questioning；要的是"从底层重构方案" → first-principles；要的是"正反论证做决定" → steel-man；要的是"把这个概念讲懂" → 本技能。
