# 反向拆解 — Reverse Deconstruction

## 设计理念

看到一个好作品，人的第一反应是"好牛"。但**赞美教不会你任何东西**——"它 UX 很好"、"设计很干净"、"以用户为中心"，这些话全对，但你没法照着做。

本技能要做的不是"描述它好在哪"，而是**反向拆解它为什么有效**：不是结论，是因果。具体到——它为了服务谁、在什么约束下、在哪个岔路口选了 A 而平庸版本选了 B，所以才拉开了差距。这个"选择 + 为什么在这个目标下这个选择更优"才是能迁移的东西。

核心信念：**"它很好"没用；"它在 X 目标下、因为 Y 约束、选了 Z 而不是 W，所以赢了"才有用。**

还有一个要主动防的雷：**cargo-cult（照猫画虎）**。范例里有些东西是它的目标/情境决定的，照搬到你这儿就错了。所以拆解必须把"可迁移的规律"和"只适合这个案例的细节"分开——否则你学到的只是形，不是神。

诚实是底线：如果拿来的"优秀范例"其实平庸或有硬伤，**先说哪里不行，再拆真正可取之处**。硬夸一个平庸范例，提炼出的"规律"会是廉价废话，害你照着平庸做。

## 工作流程

### 准备：拿到范例

从用户输入锁定**要拆解的范例**和**想学会什么**。

**输入两种来源**：
- **粘贴**（默认）：用户直接贴了内容、文本、截图描述。直接用。
- **URL**（可选）：用户给的是网址。若当前环境有浏览器 MCP（chrome-devtools / playwright / superpowers-chrome），自动抓取渲染后的内容再拆；**没有浏览器工具时不要硬撑**——降级为请用户粘贴关键内容（页面结构、文案、主要模块），并说明"我没法直接渲染这个网页"。

**最少必要提问**（能假设就假设，别把活推回用户）：
- 用户没给范例：必须问一句"拆解哪个范例？贴内容或给链接"。
- 用户给了范例但没说"想学会什么"：不问，默认按"拆它整体为什么有效"展开。
- 范例本身很模糊（比如只贴了张图没上下文）：不反问，用最合理的理解开始，在开头一句话点明你理解的范例是什么。

### 诚实性闸门

动手拆解前先过一遍：这个范例**真的好吗**？

- 如果真的好：正常往下走。
- 如果平庸或有硬伤：**先明确指出哪里不行**（具体到哪个选择有问题、为什么），再说"以下是它真正可取、值得学的部分"，然后只拆可取之处。不要为了完成流程硬夸。
- 为什么这么做：硬夸平庸范例会产出廉价规律，比不拆还害人。

### 第一步：一句话问题 + 为何有效

- **一句话说它解决了什么问题**：范例为谁、在什么情境下、解决了什么具体痛点。这一句定锚——后面所有判断都挂在这上面。没有它，"好"就没有参照系。
- **一句话说它为什么有效**：核心机制是什么（不展开，先给结论，展开留给五点分析）。

### 第二步：五点分析

逐点拆，每点都要回答"为什么这很重要"，而不是罗列现象。

**1. 它服务谁，目标是什么**
- 为什么先问这个：不锁定受众和目标，就没法判断任何选择的好坏——同一个选择对 A 用户是优点、对 B 用户是缺点。这是后面四点的尺子。
- 做到什么程度：具体到受众的真实情境和诉求，不是"面向用户"这种废话。

**2. 它采用了什么结构或流程**
- 为什么问这个：结构是骨架，决定信息/动作怎么流动。看骨架才能看出它把什么放在了前面、什么藏在了后面。
- 按成品类型自适应：
  - 网页/产品页：看信息架构、视觉层级、交互流程
  - 方案/文档：看论证结构、论点-论据-结论的排布
  - 流程说明：看步骤切分、决策点、异常分支
  - 数据看板：看指标选择、视觉编码、异常突出方式
  - 其他：按它最本质的"组织方式"看

**3. 哪些关键选择拉开了质量差距**（这是五点的心脏）
- 为什么这是心脏：前两点是"它是什么"，这一点才是"它为什么比平庸版本好"。差距不在"做了什么"，在"在岔路口选了哪个"。
- 做到什么程度：每个关键选择都要写出**平庸版本会怎么做 vs 这个范例怎么做了 differently，以及为什么在它的目标/受众下这个选择更优**。没有对比的"它选了 X"不算分析。
- 防 empty adjectives（空形容词雷）：禁止只说"流畅/清晰/好"——每个形容词必须配"哪个具体选择让它流畅/清晰"。写不出具体选择，说明还没拆到，继续挖。

**4. 它的完成标准是什么**
- 为什么问这个：每种成品有"做得好"的隐形及格线。看清范例清了哪条线，你才知道要复刻的是什么质量水平，而不是只学个皮毛。
- 做到什么程度：写出这类成品的"做好"标准（如看板：关键指标一眼可见、异常突出、不误导），并指出范例在哪几条上超标、哪几条只是达标。

**5. 哪些规律可迁移，哪些细节只适合本案例**
- 为什么这一步是防 cargo-cult 的关键：范例里有些东西是它的目标/情境/资源决定的，照搬到你这儿会错。必须切分。
- 做到什么程度：明确两栏——"可迁移规律"（换个场景仍成立的因果）和"只适合本案例的细节"（绑死在它的特定条件上，照搬会出错），并说明后者为什么不能迁移。

### 第三步：三件套

**1. 提炼 3-5 条可复用规律**
- 每条规律是一个"原则 + 为什么 + 什么条件下用"的完整句，不是口号。
- 来自第 5 点的"可迁移"那一栏，浓缩成可记忆、可套用的条目。3-5 条，不要凑数。

**2. 一份能照着执行的应用清单**
- 这是**应用清单**（不是教你怎么拆解的元方法）：把规律变成"你在自己项目里怎么复刻这种质量"的步骤。
- 如果从对话已知用户的场景/项目，按他的场景落地成具体步骤。
- 如果不知道用户场景：清单里用 `[换成你的场景]` 占位，并在末尾加一句"告诉我你在做什么，我把这份清单落地成针对你的具体步骤"——不阻塞，但留出挂钩。
- 每步要可执行（"做 X 检查 Y"），不是"注意用户体验"这种空话。

**3. 一个最值得先试的小练习**
- 一个 15-30 分钟能做完的最小动作，让用户立刻动手验证一条规律，而不是看完就忘。
- 必须具体到"拿什么、做什么、做完看什么"——比如"在你自己的落地页上，把首屏唯一主行动按钮找出来，删掉旁边所有干扰项，跑一遍看转化"。
- 只给一个，不要给一堆。第一个动作的力量最大。

**1. 服务谁 / 目标**：[具体受众 + 诉求]
**2. 结构 / 流程**：[按成品类型看的骨架 + 流动方式]
**3. 拉开质量差距的关键选择**：
  - [关键选择1]：平庸做法是 ___，它选了 ___，在它的目标下更优因为 ___
  - [关键选择2]：…
**4. 完成标准**：[这类成品的"做好"标准 + 范例在哪超标/达标]
**5. 可迁移 vs 只适合本案例**：
  - 可迁移：[规律]
  - 只适合本案例：[细节]（为什么不能迁移：___）

## 📦 三件套

**1. 可复用规律**（3-5 条）
1. [原则] —— [为什么] —— [什么条件下用]
2. …

**2. 应用清单**（复刻到自己项目）
- [ ] 步骤1：[可执行动作]
- [ ] 步骤2：…
> [若场景未知] 告诉我你在做什么，我把这份清单落地成针对你的具体步骤。

**3. 最值得先试的小练习**
> [一个 15-30 分钟可完成的具体动作：拿什么、做什么、看什么]

```
## ⚠️ 先说哪里不行
> [具体硬伤 + 为什么] —— 以下是它真正可取、值得学的部分。
```

## 边界说明

**不要做的事：**
- 不要停在"它很好"层面。每个"好"必须追到"哪个具体选择 + 为什么在它的目标下更优"，追不到就是没拆透。
- 不要用空形容词（流畅/清晰/高级）充数。写不出背后的具体选择，说明还没拆到，继续挖。
- 不要把只适合本案例的细节当成可迁移规律——那是 cargo-cult，害用户照搬错误。
- 不要硬夸平庸范例。先点硬伤，再拆可取之处。
- 不要给一堆小练习。只给一个最值得先试的，第一个动作力量最大。
- 不要在没有浏览器工具时假装能抓 URL。直接降级，请用户粘贴关键内容。

**要做的事：**
- 一句话问题要先定锚——受众和目标不清，后面全失去参照。
- 第 3 点（关键选择）必须有"平庸版本 vs 它"的对比，没对比就没拆出差距。
- 第 5 点必须切分可迁移 vs 不可迁移，这是防 cargo-cult 的关键。
- 应用清单要可执行、可照着做，每步是动作不是口号。
- 小练习要 15-30 分钟能做完、能立刻验证一条规律。
- 按成品类型自适应第 2 点的"结构/流程"视角，不要用看网页的视角去看流程文档。

## 力度控制

**默认行为**：五点全拆、三件套做全，最大诚实。

用户可在请求中调整：
- `--quick`：压缩成"一句话 + 关键选择 3 条 + 规律 3 条 + 一个练习"，跳过结构/完成标准的展开（适合快速过一遍）。
- `--deep`：第 3 点每个关键选择都展开平庸版本的完整分析，适合要真正吃透一个范例。
- 用户直接描述（如"快速拆一下"、"这个我要吃透"）同样生效。

## 与其他技能的区分

- **dual-layer-explanation**：把一个概念分两层讲懂。本技能拆的是**成品/作品**为什么有效，不是讲概念。
- **agentseo**：从 AI 智能体视角审计一个网站对 agent 友不友好（5 维度打分）。本技能是**从人学习的视角**拆解成品为什么好，不做可读性评分。
- **hv-analysis**：对一个产品/公司做纵向生命历程 + 横向竞品对比的深度研究。本技能是**单点拆解一个范例的因果**，不做横向对比或生命史。
- **adversarial-review**：红队批判找致命弱点。本技能是**拆解为什么有效 + 提炼可迁移规律**，不是找漏洞（除非范例真有硬伤，那是诚实性闸门的事）。
- 当用户要的是"讲懂一个概念" → dual-layer-explanation；"审计网站对 AI 友不友好" → agentseo；"深度研究一个产品/公司" → hv-analysis；"批判找漏洞" → adversarial-review；"学这个好作品到底好在哪、怎么用上" → 本技能。
