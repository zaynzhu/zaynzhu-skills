# 专家会诊 — Expert Panel

## 设计理念

以前流行在 prompt 开头写"你是一位拥有 20 年经验的世界级专家"。但很多问题不属于单一专业——它是几个专家互相配合才能想清楚的。单专家视角的盲区，恰恰是另一个专业的常识。

所以这个技能不扮一个专家，而是**自组一个真正互补的小型专家团，再让他们互相挑战**。

核心信念：**真正的信息，往往都在分歧里。** 三个视角都同意的部分，多半是常识；真正的洞察诞生在他们的分歧处——分歧背后是不同的假设，把假设翻出来，才知道该去验证什么。所以整个流程最关键的一步不是"各抒己见"，而是**互相质疑**：逼每个视角说出"其他视角最容易忽略的风险"，再把分歧背后的假设挖出来。

互补是底线，同质化是失败。三个高度相似的身份（比如三个工程师、三个"资深专家"）等于一个视角乘三，互相质疑就变成互相附和。所以选视角时必须保证：每个视角都结构性地看到其他视角看不到的东西。

不模仿、不编造真实人物。选的是**专业视角/学科/职能/立场**，不是"某某真人会怎么说"，也不是"20 年经验的 XX 专家"那种空 persona——要写清这个视角关心什么、为什么对这个问题必要。

## 工作流程

### 准备：拿问题 + 判断信息是否够

从用户输入提取四样：**问题、已知事实、目标、现实约束**。

**信息不足时，先只问一个最关键的问题**——不要问一堆。判断标准：是不是缺了某一块，连互补视角都组不起来、或者组起来也是空谈？如果是，问那一个最关键的（通常是"你最重要的目标是什么"或"最硬的约束是什么"）。如果不缺，直接开始，别把活推回用户。

### 第一步：选 3 种真正互补的专业视角

为这个问题选 3 个视角，**每个都要说明为什么必要**。

**互补的标准**：每个视角都结构性地看到其他视角看不到的东西。好互补是覆盖不同维度——技术/商业/用户、短期执行/长期战略/风险、工程/财务/法务。**测试**：如果两个视角会给出相似答案，换掉一个。

**不要**：
- 三个高度相似的身份（三个工程师、三个管理者）
- 模仿或编造真实人物的观点（"马斯克会怎么说"）
- "20 年经验的世界级 XX 专家"这种空 persona——要写视角关心什么，不是堆头衔

每个视角用一段话写清：它是什么专业立场、它对这个问题关心什么、为什么缺了它这个会诊就残缺。

### 第二步：各视角独立回答 4 问（子 Agent 独立）

**默认用 3 个并行子 Agent**，在同一轮里同时派出，每个子 Agent 只拿到问题 + 自己被分配的视角，**互不见对方答案**——保证独立，不被彼此带跑。

给每个子 Agent 的 prompt 模板：

> 你是 [视角名称] 视角。你的专业立场是 [这个视角关心什么]。
> 问题是：[问题、已知事实、目标、约束]
> 请只从这个视角回答 4 问，不要扮演别的视角：
> 1. 你怎样重新定义这个问题（你认为问题的本质是什么）
> 2. 你最推荐的解决路径
> 3. 其他视角（别的专业）最容易忽略的风险是什么
> 4. 什么新证据会让你改变判断
> 直接给结论和理由，不要寒暄。

**第 4 问是分化器**：逼每个视角说出"别人最容易忽略的风险"，想答好就必须真的站在自己视角、看到别人看不到的——这从结构上防止同质化。

**无子 Agent 时降级为内联扮演**：主 Agent 在同一上下文依次扮演 3 视角，每视角写成独立小节、各自答 4 问。降级时更要严格执行"第 4 问必答别人忽略的风险"来强制分化，否则三个视角会塌成一个。

### 第三步：互相质疑（默认一轮）

把 3 个视角的独立回答放在一起，让他们**互相质疑**。这一步是技能的核心——不是各抒己见就完事，要挖分歧。

找出三样：
1. **共同认可的事实**：三个视角都同意的（这些多半是常识，是方案的稳定地基）
2. **真正的分歧**：不是表面吵的点，而是"定下它结论就变"的底层分歧
3. **分歧背后的不同假设**：每个分歧背后，各方默认了什么不同的前提？——这才是要拿去验证的东西

**`--deep` 多轮**：默认一轮。重要决策用 `--deep`：质疑后把质疑点发回给各视角（子 Agent）回应，再质疑，迭代至分歧稳定或上限 3 轮，再进入综合。日常问题一轮就够，不要拖。

### 第四步：综合输出（单一方案 + 保留分歧）

综合，给一个**最推荐的方案**——但**不把分歧消化掉**，而是把它带出来。因为你说过，信息在分歧里。

综合输出五件：
1. **综合后最推荐的方案**：明确一个，不和稀泥
2. **适用条件**：这个方案在什么条件下成立
3. **最大风险**：最可能让它崩的单一风险
4. **退出条件**：什么时候该放弃这个方案、切换到分歧中那个反对视角的路径——挂钩到"那个假设被证伪/证实"。即：反对视角基于假设 X 反对，当 X 被验证为真时，退出当前方案、切到反对视角的路径
5. **第一步行动**：具体可执行的下一步

**保留分歧**：在综合输出里显式带出未决分歧——哪个视角反对、基于什么假设、什么新证据会翻盘。退出条件就是从这些来的。

## 边界说明

**不要做的事：**
- 不要选三个高度相似的身份。互补是底线，同质化等于一个视角乘三，互相质疑变成互相附和。
- 不要模仿或编造真实人物的观点。选专业视角，不是"某某真人会说"。
- 不要用"20 年经验的世界级专家"这种空 persona。要写视角关心什么，不是堆头衔。
- 不要跳过互相质疑。各抒己见不是会诊，挖出分歧和背后假设才是。
- 不要在综合时把分歧平滑掉。带出来——信息在分歧里，退出条件从分歧来。
- 不要在子 Agent 模式下让视角互相看到对方答案才作答。独立性是互补的前提。
- 不要信息不足时问一堆问题。只问一个最关键的。

**要做的事：**
- 选视角时用"两个会给出相似答案就换掉一个"这个测试把关互补性。
- 每个视角必须答第 4 问（别人最易忽略的风险）——这是强制分化的结构。
- 互相质疑要挖到"分歧背后的假设"，不只是列分歧。
- 综合给单一方案，但退出条件挂钩到反对视角的假设验证。
- 第一步行动要具体可执行，不是"可以再权衡"。
- 无子 Agent 时降级内联，但更要靠第 4 问强制分化。

## 力度控制

**默认行为**：3 子 Agent 独立 + 一轮质疑 + 单一方案保留分歧。

- `--deep`：质疑多轮迭代至分歧稳定或上限 3 轮（重要决策用）
- `--inline`：强制内联扮演，不派子 Agent（无子 Agent 环境或要快速跑时用）
- `--quick`：2 视角 + 一轮质疑 + 压缩输出（小问题用）
- 用户直接描述（如"这个问题很重要多挖几轮"、"快速碰一碰"）同样生效

## 与其他技能的区分

- **model-debate**：多个 AI **模型**互相辩论/合成共识。本技能是**多个专业视角**（同模型的并行子 Agent 或内联扮演），不是多模型。
- **steel-man**：已有立场，正反两面都构建到最强后做决定。本技能不预设立场、不正反二分，而是**3 个互补视角互相质疑**。
- **adversarial-review**：红队单方面批判找致命弱点。本技能是**多视角对撞**，不是一方批一方。
- **socratic-questioning**：追问澄清用户真正想问什么。本技能是问题已明确后**组专家组想方案**。
- **enhanced-hv-analysis**：系统研究一个对象的发展史+竞争格局出长报告。本技能是**对一个决策问题做多视角会诊出方案**。
- 当用户要"多模型辩论" → model-debate；"正反论证做决定" → steel-man；"红队找弱点" → adversarial-review；"我没想清问什么先追问我" → socratic-questioning；"组个互补专家组互相质疑给方案" → 本技能。
