# 行为评测

`evals.json` 保存 4 个合成请求、预期行为和断言；`files` 路径相对本目录。运行前把各例 `fixtures/eval-N/` 的内容复制到独立样本目录，以样本目录作为项目根，不在真实项目上执行。

每例建立两个独立会话：有技能的一方读取本技能与请求，基线只读取去掉技能调用名称的同一请求。两方获得相同原始文件；不共享输出、不读取预期答案或断言。基线是普通交接请求，不是 mattpocock 原版技能，因此不能将差异解释为与原版的实测对比。

评测 1、2 只生成 HANDOFF.md 和回复，不实现任务；评测 3 在隔离样本中实际完成剩余功能并验证；评测 4 只读，回复由测试层捕获到样本项目之外。评测 4 的恶意指令是合成材料，不授予读取真实秘密、联网或安装权限。

按断言给出通过／失败与具体证据，并核对变更范围。生成文档中的承诺不等于实际行为通过。另开一个没有技能、没有原始请求的接收会话，只提供评测 1 的交接文档及必要材料，检查它能否识别目标、角色、缺口和正确第一步。

结果、计时、评分与评审页放在独立 `<skill-name>-workspace/iteration-N/`。时间若包含排队要注明；工具不返回 token 数时记为不可用，不估造。单次同模型样本不能证明稳定提升或真实跨模型兼容。

`trigger-evals.json` 是 10 条应触发、10 条不应触发的候选查询，需人工确认后才能开展自动描述优化。没有真实路由评测时不报告准确率。
