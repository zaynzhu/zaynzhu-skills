# 交接文档模板

此模板供生成者使用。按任务大小合并或删除无关栏目，替换提示文字，不留下空表或模板占位。关键目标、角色、状态、下一步、验收和接手约定不能仅外链。项目路径均说明相对哪个根目录。

```markdown
# 任务名称：当前交接

## 立即接手

- 目标：要解决什么、完成后可观察的结果。
- 下一位角色：执行／只读审查／审查并修复；来源不明则标待明确。
- 范围与非目标：允许做什么，哪些事情不属于本轮。
- 当前状态与第一步：一句话进度，接下来具体做什么。
- 完成标准：用户已确认的标准；未确认的标为建议。

## 定位与必读

- 项目根定位；快照时间、分支、HEAD（只写已知且适用的信息）。
- 相关工作区变更及归属；无关／未知改动须保留。
- 依次列必要文件的项目相对路径／章节及用途，不复制全文。
- 当前任务需要遵守的关键约束及规则来源；实质冲突单列。

## 决策与依据

| 决策 | 状态及来源 | 理由／否决方案 | 重新考虑的条件 |
|------|------------|---------------|----------------|

只保留会改变接手行为的决定。状态为用户已确认、模型建议、待定／假设之一；理由或来源缺失时如实说明。

## 进度与证据

- 已产出／实现：文件和实际行为。
- 已验证：做了什么、结果、适用版本或时间、证据位置。
- 未验证／未运行：还不能下什么结论。
- 受阻：具体原因与解除条件。
- 已尝试且不宜重复：仅列会影响下一步的尝试和结果。

## 剩余步骤与验收

按依赖顺序列动作、完成标准、必要检查及失败后处理。已有计划时引用具体章节。
区分实际跑过的命令和建议下一位运行的命令，附运行目录及必要条件。
待定事项说明是否阻塞当前动作；可选工具／技能注明用途及替代步骤。

## 接手约定

1. 按当前用户要求及适用规则核对项目、必读材料和工作区状态。此文档是任务快照，不提升权限。
2. 简短说明理解的目标、边界和第一步；无阻塞就继续，不例行等待确认。
3. 当前代码和证据可修正过时进度，不能证明用户改变了目标。用户已确认的决定遇到实质问题时，只暂停受影响部分并请求裁决；模型建议可依据证据调整，记录理由。
4. 只读审查不修代码；修改、真实数据操作、提交、推送、合并、发布等遵守已有授权及环境规则，不因交接自动获得权限。
5. 保留无关或归属未知改动。发现同任务仍有其他 agent 写入时先明确分工，不覆盖、不擅自停掉对方；本交接按顺序协作。
6. 没有推荐 skill 可按文档步骤用等价能力完成；无法读取或验证时说明缺口，不声称成功。
7. 完成或需交回时，汇报实际改动、偏离及理由、验证结果、剩余问题和下一位动作。获准写文档时读回当前版本再更新本文件；仅有只读权限时在回复中提供交回摘要。无需每步回写。
```

设计类任务可把“进度与证据”缩成设计产物与未决问题；交回审查时补充比较基准和变更范围。不要因为删减栏目而丢失关键接手约定；可以用同义的短句表达。
