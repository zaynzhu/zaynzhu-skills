# 增强版横纵分析法深度研究

> **方法论溯源**
> 横纵分析法融合索绪尔历时-共时分析、社会科学纵向-横截面研究设计、商学院案例研究法与竞争战略分析。本增强版在原版框架上吸收了更锐利的分析刀（路径依赖/包袱、选择与放弃、预警信号）和更严的证据纪律（可追溯、事实推断观点分离、冲突并列），让研究不止"讲清楚它怎么来的"，更能"追溯每条结论的依据、指出哪些还没核实"。

## 相对原版的 6 处增强

| # | 增强 | 原版状态 |
|---|------|---------|
| 1 | **可追溯**作为一类原则 + 研究截止时间=执行当天 | 原版有来源但没强调可追溯/截止时间 |
| 2 | 纵向收口于：早期选择→今天的**能力 / 路径依赖 / 包袱** | 原版提"决策锁定"但没这把刀 |
| 3 | 横向收口于：**为什么选它 + 为什么放弃它** | 原版有用户视角但没"选择 vs 放弃"配对 |
| 4 | 未来**3 条路径 + 各自前提 + 预警信号** | 原版 3 剧本但没预警信号 |
| 5 | 证据规则：**就近标注来源+日期、事实/推断/观点分开、冲突并列、"暂未核实"** | 原版有"标注来源/不编造"但没这四条精细纪律 |
| 6 | 输出顺序：**核心结论→关键时间线→横向对比表→详细分析→未来判断→仍待确认的问题** | 原版顺序是定义→纵向→横向→交汇→来源 |

## 前置准备

### 明确研究对象与截止时间

拿到用户输入后确认（给得够明确就别追问，直接开始）：

1. **研究对象**：具体名称
2. **类型**：产品 / 公司 / 人物 / 技术 / 行业 / 事件（原版无"行业/事件"，本版补上）
3. **研究截止时间 = 执行当天**：所有"当下""现状""最新"判断都以执行当天为时间截面。在报告里写明截止日期，超过该日期的信息不得当作"现状"。
4. **研究动机 / 特别关注点**（可选）

### 环境准备

- PDF 转换脚本：本技能自带 `scripts/md_to_pdf.py`（基于 WeasyPrint）。依赖：`pip install weasyprint markdown`。无 WeasyPrint 时降级为只交付 Markdown（见 `references/pdf-output.md`）。
- 写作风格：写作前必读 `references/writing-style.md`。

## 证据规则（本增强版的核心纪律）

这一节是本版相对原版最大的差别。研究质量 = 信息质量 × 诚实度，证据规则管的是诚实度。

**1. 一手来源优先。** 官方博客/Release Notes/创始人推文 > 权威媒体原创 > 转载聚合。多个媒体引用同一错误会造出"循环印证"假象，要追到原始来源。学术/技术类必查 arXiv。

**2. 重要结论就近标注来源与日期。** 不是只在末尾列个来源清单——每个重要结论**就近**标 `[来源，日期]`。日期和来源一样重要：2023 年的数据不能支撑 2026 年的"现状"判断。

**3. 事实、推断、观点分开写。** 三者必须可区分：
- **事实**：有来源支撑的客观陈述
- **推断**：由事实合理推出的结论，标注"据此推断"
- **观点**：研究者主观判断，用"我的判断是 / 我认为"承认主观性
不要把推断伪装成事实，也不要把观点伪装成推断。

**4. 冲突信息并列呈现，找不到证据写"暂未核实"。** 遇到来源冲突，不要悄悄选一个——并列呈现两个说法 + 各自来源，让读者自己判断。某个信息搜不到，明确写"该信息暂未核实"，绝不编造、绝不拿训练记忆充数。

## 第一步：联网信息收集

质量取决于信息的丰富度和准确性。**必须联网搜索**，不能仅靠已有知识。宁可多搜，不要因信息不够导致后面分析浮于表面。

### 并行搜索策略

用子 Agent 并行搜索（复杂对象用 3 个，简单对象 2 个）：

- **子 Agent 1 — 纵向**：起源、创始人背景、发展历程、关键事件、版本迭代、融资、战略转向、危机与失败
- **子 Agent 2 — 横向**：竞品识别、各竞品特点与用户口碑、行业对比评测、市场份额
- **子 Agent 3（复杂对象才需要）**：创始人深度背景、行业环境变化、用户社区真实声音（GitHub Issues / Reddit / X / 知乎）

**每个子 Agent 的 prompt 必须写入联网指引**：
> 你需要联网获取信息。WebSearch 发现来源、WebFetch 定向提取；已知 URL 用 WebFetch。多次搜索、多关键词组合，不要只搜一次。一手来源优于二手。学术/技术类必查 arXiv：`curl -s "https://export.arxiv.org/api/query?search_query=all:关键词&max_results=10"`。每个关键事实记下来源 URL 和日期。搜不到的写"暂未核实"，不编造。

prompt 用"获取/调研/了解"等目标动词，不用"搜索/爬取"等手段动词，让子 Agent 自主判断最佳获取方式。

### 来源优先级

| 信息类型 | 一手来源 |
|---------|---------|
| 产品更新/技术决策 | 官方博客、GitHub Release、创始人推文 |
| 融资/商业数据 | 公司公告、SEC/工商文件 |
| 用户口碑 | GitHub Issues、Reddit、X、知乎 |
| 行业分析 | 权威媒体原创（非转载） |
| 学术/技术原理 | arXiv、Google Scholar、会议论文集 |

### 充分性自检

- 纵向：能讲出完整故事吗？有明显信息断层吗？
- 横向：竞品列表完整吗？每个竞品信息够做对比吗？
- 来源：关键事实有可靠来源吗？有没有只靠单一来源就下判断？冲突信息处理了吗？

不够就补搜，不凑合。

## 第二步：纵向分析（历时）

沿时间轴完整还原从诞生到现在的发展全貌。这是报告主体，篇幅最重。

### 内容要求

- **起源追溯**：诞生背景（时代/行业/技术环境）、诞生动机（解决什么问题/填补什么空缺）、关键推动者是谁、这些人之前做过什么/为什么是他们、初始形态与现在有何不同、有没有种子事件直接促成诞生。
- **演进历程**：按时间梳理所有关键节点——重大版本/融资/团队变动/战略转型/架构变化/用户里程碑/重大合作或收购/**公关危机或失败**。成功和失败都要写，失败往往比成功更说明问题。
- **决策逻辑**：每个节点还原"为什么选 A 而不是 B"、当时约束是什么、哪些早期决策"锁定"了后来方向难以逆转、什么机制让它越走越深（网络效应/生态绑定/技术栈）。
- **阶段划分**：自然分为萌芽期/快速增长期/转型期等，每阶段有核心特征和核心矛盾。

### ★ 路径依赖收口（本版增强）

纵向分析的收口必须是这一问：**哪些早期选择，变成了今天的能力、路径依赖或包袱？**
- **能力**：当年某个选择沉淀成了今天的核心优势
- **路径依赖**：当年某个选择锁死了今天的方向，想转成本极高
- **包袱**：当年一个"好决策"，今天变成了拖累
这一问把"历史故事"变成"对当下的解释力"——是纵向分析的价值所在，不要省。

### 篇幅

6000-15000 字。历史越长越靠近上限。宁可写长写细，不要蜻蜓点水。

## 第三步：横向分析（共时）

以执行当天为切面，与同赛道竞品/同类系统对比。

### 先判断竞品场景

- **场景 A 无直接竞品**：跳过逐一对比，改为分析它为什么没有竞品（品类太新/壁垒太高/市场太小）、未来最可能从哪冒出竞争者、有没有间接替代或上一代方案可参照。
- **场景 B 少量竞品（1-2）**：逐一深入展开。
- **场景 C 竞品充分（3+）**：选最具代表性的 3-5 个，其余简要提及。

### ★ 选谁要比，要说明为什么

不要默认抓大放小。**明确说明为什么选这几个比较对象**——是直接竞争、同需求替代、还是潜在威胁？选错了比较对象，整个横向分析就歪了。

### 统一维度对比

用**统一维度**把研究对象和竞品拉到一起比，每个维度写清各方的**强项 / 短板 / 独特性**：
- 技术路线/核心方法论、产品形态/商业模式、目标用户/适用场景、定价/规模体量
- 不要写成参数对照表的文字版，要讲清每个竞品"活成了什么样"

### ★ 选择 vs 放弃（本版增强）

横向分析的收口必须是这一对：**用户/客户/市场为什么选它，又为什么放弃它？**
- **为什么选**：真实选择理由（常和官方定位有偏差，要去社区听真实声音）
- **为什么放弃**：流失理由、吐槽、迁移到谁那里
这对把"竞品参数对比"变成"市场用脚投票的因果"——是横向分析的价值所在。

### 篇幅

3000-10000 字。场景 A 约 3000，场景 C 每个主要竞品至少 1500 独立分析。

## 第四步：横纵交汇

这是精华段。把纵向脉络和横向格局编织在一起，给新判断，不是前面内容的缩写。

### 必答

1. **历史如何塑造了当下的竞争位置**：纵向哪些决策/事件，决定了它今天在横向对比中的位置？
2. **竞品的纵向对比**：把主要竞品也放时间线上，它们的起源和演变路径有何不同？这些不同如何导致今天各自特点？
3. **优势/劣势的历史根源**：今天每个核心优势/劣势，能追溯到历史哪个节点或决策？当初的"好决策"有没有变成今天的包袱？（接纵向的路径依赖收口）

### ★ 未来 3 条路径 + 前提 + 预警信号（本版增强）

不要只给"最可能/最危险/最乐观"三剧本。给出 **3 条未来路径**，每条都要写清：
- **路径描述**：这条路通向什么
- **前提**：这条路出现需要什么条件成立
- **预警信号**：观察什么信号能提前判断它正在走这条路（具体可监测，不是"关注市场动态"这种空话）
预警信号是本版的关键——它把"未来推演"变成"可以现在就盯着看的指标"。

### 篇幅

1500-3000 字。

## 写作风格

写作前必读 `references/writing-style.md`。要点速览：
- 叙事驱动不是罗列驱动，纵向要有故事弧线，不是"2023 年 1 月发布 A，3 月发布 B"流水账
- 知识是"聊着聊着顺手掏出来"，不是"下面科普一下"
- 敢下判断但每个判断有事实支撑；推断标"据此推断"，观点用"我的判断是"
- 节奏感：句长句短交替，一句话自成一段制造重量感
- **绝对禁区**：禁"首先…其次…最后""综上所述""值得注意的是""赋能/抓手/打造闭环""说白了/本质上/换句话说"；禁教科书开头；搜不到诚实写"暂未核实"，绝不编造
- 报告保留清晰章节结构（不像公众号去小标题），冒号破折号可正常用

## 第五步：输出与 PDF

### 输出顺序（本版重构）

按以下顺序输出，**核心结论先行**（不是定义先行）：

1. **核心结论**：3-5 句话说清它是什么、最关键的判断是什么。先给结论，让读者拿到锚点。
2. **关键时间线**：纵向的核心节点压缩成一条可扫读的时间线（不是完整叙事，完整叙事在第 4 段）。
3. **横向对比表**：统一维度的对比表（结构化，一眼可读）。
4. **详细分析**：完整的纵向叙事 + 横向展开 + 横纵交汇（报告主体，承载字数）。
5. **未来判断**：3 条路径 + 各自前提 + 预警信号。
6. **仍待确认的问题**：本研究没核实清楚的问题清单（诚实留白，对应证据规则 4）。

末尾附**信息来源**（所有引用来源 + URL + 访问时间）和**方法论说明**（1-2 句）。

> 顺序记忆口诀：**结论 → 时间线 → 对比表 → 详细 → 未来 → 待确认**。

### 生成 PDF

Markdown 完成后用 `scripts/md_to_pdf.py` 转 PDF（步骤、Markdown 写法、排版规范见 `references/pdf-output.md`）。无 WeasyPrint 则只交付 Markdown 并说明。

文件命名：`[研究对象]_横纵分析报告.md` / `.pdf`，存到用户工作目录。

## 类型适配

核心不变（纵向追时间深度，横向追同期广度），侧重不同：

- **产品**：纵轴重版本迭代/技术路线/用户增长/关键决策；横轴重功能/性能/体验/定价
- **公司**：纵轴重创始团队/融资/战略转向/组织变革；横轴重商业模式/市场份额/营收
- **人物**：纵轴重职业轨迹/关键决策/公开言论变化；横轴重与同领域人物的做事风格/路线差异
- **技术**：纵轴重起源（谁提出/基于什么理论）/演进/争论；横轴重与相近技术的区别/适用场景
- **行业**：纵轴重形成与演变/关键转折/政策与技术驱动；横轴重细分赛道格局/参与者对比
- **事件**：纵轴重起因经过结果/关键角色/转折；横轴重与同类事件/历史相似事件的对比与启示

## 与原版 hv-analysis 的区分

本技能 = 原版 hv-analysis 的**增强版**：吸收原版全部框架（纵向/横向/交汇、写作风格、PDF、1-3 万字、类型适配），在上面加了上表 6 处增强。核心差异是**更可追溯**（证据规则 + 截止时间）、**更锐利**（路径依赖/包袱、选择与放弃、预警信号）、**结论先行**（输出顺序重构）。
