# 阻塞与替代路径

| 真实阻塞 | 优先处理 | 仍不可行时的具体交付 |
|---|---|---|
| 没有 GitHub 仓库/没有登录 | 检查已有 GitLab、其他云端 CI 或用户提供的远端构建机 | 完整容器文件、适配已有 CI 的步骤；询问源码可上传的仓库，不自动公开源码 |
| 无写入/工作流权限 | 完成最小 diff、检查所需权限和 ref，给有权限者可执行的提交/触发步骤 | 指定 workflow、输入、配置项和预期 artifact，状态“已生成” |
| Actions 禁用/额度不足 | 查明组织策略或额度问题，优先已有获准云端 runner | 给另一个已授权云端服务的执行方案；新费用先说明并获授权，不承诺免费 |
| 手动触发找不到 workflow | 检查默认分支 workflow 注册情况和选择的 ref | 准备最小 PR/变更及默认分支接入步骤，不擅自合并 |
| 构建失败 | 抓具体失败日志，按锁文件、上下文、缺失产物、系统依赖修复 | 给最小复现、精确差异和剩余阻塞，最多少量有依据重试 |
| 架构不支持/仿真慢或失败 | 换已授权的目标架构原生云端 runner；检查依赖是否发布该架构 | 交付支持架构和不支持证据，提供替换依赖/远端服务方案；不伪造多架构支持 |
| 内网依赖/私有包无法访问 | 云端 secret、授权网络或位于可访问网络的远端 runner | 给需配置的变量名和网络条件；不上传本地凭据，不绕过访问控制 |
| tar 超限/云端磁盘不足 | 缩减构建上下文与运行层、按服务或架构拆包，评估临时文件占用 | 提供分包与重组/校验说明，或经用户选择改仓库/对象存储；不无限提高资源 |
| 包成功但无法启动 | 用交付包复现缺镜像、路径、权限、环境变量、数据库就绪/迁移问题 | 保留“已构建”，列出修复和待验证项；不得报告“部署完成” |
| GPU/NAS 特性无法在 CI 验证 | 另选具备相应硬件的已授权云端测试资源 | 构建包加目标机验收步骤，明确未验证硬件行为 |
| 原生平台能力不能容器化 | 给代码/依赖证据，圈出可容器化服务 | 原生云端构建产物、后端分离或远程运行的落地步骤，不声称已有 Docker 包 |
| 所有云端路径受阻 | 保存全部生成文件、失败证据和恢复条件 | 给具体云端解锁步骤；只列“明确授权后可尝试本地 Docker”为最后备选，不执行、不诱导安装 |

新服务、新付费、私有代码外传或目标机部署缺少授权时，仅暂停该依赖动作；文件准备、静态检查和可审阅方案继续完成。用户已明确授权的操作不再重复询问。
