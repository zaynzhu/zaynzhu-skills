# 项目适配指南

先沿用项目已验证的运行方式；这些是决策提示，不是可直接复制的版本模板。

| 项目类型 | 构建与运行关注点 | 最小验收 |
|---|---|---|
| Node / monorepo | 锁文件、workspace 包、代码生成、生产依赖裁剪后是否仍需 CLI；Alpine 的 libc 与原生模块兼容性 | 从实际产物启动，检查共享包与原生模块加载 |
| 静态前端 / SSR | 区分编译时公开变量与服务端秘密；浏览器不能解析 Compose 服务名；静态资源路由、反向代理与 SPA 回退 | 从用户访问端口贯通页面及 API，SSR 真正启动 |
| Python | 按锁文件/约束安装、系统库与平台 wheel；生产 server 与 worker 分离 | 导入关键模块、HTTP/任务执行成功 |
| Java / Go / Rust / .NET | 运行版本、原生链接、证书、动态库、目标 OS 和 CPU；不要只判断二进制文件存在 | 目标架构启动及实际请求/命令 |
| 数据库 / 缓存 | 既有服务还是随包部署；锁定兼容版本；真实持久化路径、就绪与恢复 | 临时实例初始化、写读、重建容器后数据保留 |
| 定时任务 / worker / CLI | 是否应为长驻服务，默认禁用真实调度；不得添加无意义端口或伪健康接口 | 单次安全任务结果/退出码、优雅退出 |
| GPU / 大模型 | 驱动、设备访问、CUDA 等兼容性、模型授权与权重体积、云端硬件 | 无 GPU 时只声称构建，提供有 GPU 的云端验收入口 |
| Windows 服务 / macOS / iOS / Android / 浏览器扩展 / 纯库 | 区分交叉编译环境与产品运行平台；原生 UI、平台框架、驱动不等于 Linux 服务 | 能拆后端则单独容器化；否则交付原生云端构建路线和不可容器化依据 |

## 运行契约

- 绑定到容器可访问地址，端口映射不改变应用监听地址。仅暴露必要服务，未认证管理接口不新增公网暴露。
- `depends_on` 不代替应用重连。健康命令必须实际存在于最终镜像；启动时间、迁移完成和就绪分开判断。
- 只将可变数据持久化，避免卷覆盖镜像内程序；bind mount 和命名卷分别说明权限。尽量非 root，不靠全目录 `777` 解决权限。
- 将数据库 schema 迁移与应用启动区分；默认不自动执行破坏性同步。明确备份及旧程序是否兼容新 schema，不能承诺换回镜像就能回滚数据。
- 现有 `.env` 可能含密钥，只检查变量名/配置状态，不打印值。前端构建产物中任何变量都视为公开。
- 秘密依赖使用云平台 secret 与 BuildKit secret mount，避免 `ARG`/`ENV`、日志、镜像层和共享缓存暴露 token；无凭据时交付变量名与配置步骤，不要求用户在聊天里粘贴。
- 离线范围分清：无需源码、无需下载镜像、完全不联网是三种不同承诺。运行中下载模型、pip/npm 包也破坏完全离线条件。

## WhatsNew 修复中提炼的易错点

- 校验和不能包含构建机的 `dist/` 前缀或绝对路径；在包目录内对相对文件名计算，换目录解压后再次验证。
- Compose 解析会检查 `env_file` 存在。云端验证打包目录中的 Compose 时，在相同相对位置临时创建无敏感配置，验证后清理；不要为了通过校验复制真实设置。
- 镜像中 `chown` 不能决定 bind mount 后宿主目录的权限；以实际运行 UID/GID 测试挂载目录写入。设置页使用临时文件 + rename 时，不只文件，父目录也必须可写，应挂载配置目录，不能盲目只挂载单个文件。
- 修改 `env_file` 的值后需要重建容器，普通 restart 不重新注入容器环境；与应用自己支持的热加载分开说明。
- 缓存是运行时写路径，即便叫缓存也必须验证普通用户能创建子目录；跨容器重建需要保留的缓存明确挂载。
- 本地开发依赖或生成物可能掩盖干净构建错误。显式检查生成客户端、共享包、系统库和最终启动文件，不能依赖开发机 node_modules。
- 有旧实例时，迁移步骤包含唯一 scheduler/worker 的切换，先关闭新实例副作用，验收后再切换；不要让两套任务同时写真实数据库。
