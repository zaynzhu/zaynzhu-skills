# 评测说明

`evals.json` 包含 4 个合成情境：正常路径 2 个、边界 1 个、对抗 1 个。每例 4 条检查，主要覆盖错误前提、实际验证、工程边界和执行偏差。`trigger-evals.json` 包含 10 个明确调用和 10 个不应自动触发的查询。

首轮已在同模型的 8 个独立上下文中运行技能与无技能对照，两组均通过 16 项检查。评分由主智能体按断言执行，非盲测。第 3 例的“未完成运行验证”按未完成真实系统验证理解，允许如实标注的局部模型实验。

这些结果不证明技能优于基线，也不证明跨模型接手效果或额度节省。每例仅运行一次；token 数据不可得，时间采样边界不统一，不进行效率比较。真实项目、跨能力执行者接手、平台明确调用机制尚未验证。

维护时将实际输出、逐条评分、计时与反馈放在独立工作区，日常使用不加载它们。首轮反馈已通过，分析后保留当前正文。全部断言在本轮无组间判别力；后续应重点验证独立接手效果，并在运行前澄清第 3 例对真实系统验证的要求。未运行描述优化或平台路由评测；明确调用边界不为提高自动触发率而放宽。
