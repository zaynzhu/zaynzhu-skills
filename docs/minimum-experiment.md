# Minimum Experiment — 用最小实验替代空想

## 一句话

当一个决定继续纸上谈兵也不会更清晰时，找背后 3 个假设、选最可能改变结论的那一个，围绕它设计一个低成本、可逆、7 天内能完成的最小实验（做什么/投入/指标/支持继续/提醒停止/能学到什么），给明天能开始的第一个动作；跑完带结果回来，再帮解读结果、判断继续/调方向/停止。

## 设计理念

有些决定继续想不会更清晰——缺的不是更多推理，是现实世界的反馈。再纸上谈兵是在没数据的世界打转。该迈出一步去试，让现实给你数据。

但乱试有代价，所以用最小实验：找最关键的假设，用最低成本、可逆的方式验证它。Lean Startup 的验证式学习用到决策上。

三个核心信念：
- **假设驱动**：3 个核心假设里有一个最 load-bearing，它若假整个决定就翻。集中验证这一个。
- **可逆优先**（Bezos 决策分类）：把"看似一类"的不可逆决定降级成"可逆的小试"。不可逆的"实验"是赌博不是实验，要拒绝。
- **三原则**：低成本（失败不心疼）、可逆（能退回）、周期内（默认 7 天出结果）。

6 件输出防糊弄：光说"试试看"没用，尤其"支持继续/提醒停止"判定线要在跑前定好，避免跑完凭心情解读成"好像还行"。

## 触发方式

说以下任意一句即可触发：

- "最小实验 / 帮我设计个实验"
- "纠结试试看 / 迈出第一步验证一下"
- "纸上谈兵没用了想试试 / 不敢决定先试一下"
- "用小测试验证假设 / 帮我设计个低成本可逆实验"
- "minimum experiment / 现实反馈验证"

即使用户说"这个决定继续想也没用"、"纠结好久了想迈出第一步"、"帮我试试这个想法可不可行"，也应触发。

**关键区分**：回本行业本质重推 → first-principles；正反论证后定 → steel-man；追问澄清真问题 → socratic；验说法真假 → fact-check；组专家组对撞 → expert-panel；纠结决定用最小实验问现实 → 本技能。

## 工作流程

### 第一轮：设计
1. 找 3 个假设，选最可能改变结论的 1 个（load-bearing）
2. 围绕它设计最小实验（低成本/可逆/7天内；不可逆的要改成可逆）
3. 写清 6 件：做什么 / 投入 / 观察指标 / 支持继续的判定线 / 提醒停止的判定线 / 能获得的新信息
4. 给明天能开始的第一个动作

### 第二轮：解读（用户跑完带结果回来）
对照预设判定线判断：继续推进 / 调方向 / 停止。给下一步（可能是下一个实验——实验是迭代的）。结果模糊不强行下结论，指出缺什么、要不要补跑。

## 力度控制

- 默认：3 假设选 1 + 6 件实验 + 明天第一个动作
- `--quick`：只给最关键假设 + 一句话实验 + 第一个动作
- `--serial`：直接设计 2-3 个串行实验路线（重要决定迭代验证多假设）

## 与同类技能的区分

| 技能 | 做什么 | 何时用 |
|------|--------|--------|
| **minimum-experiment** | 设计最小实验问现实 + 解读结果闭环 | 纠结决定想不清，该试试 |
| first-principles | 回本质重推导，结尾给验证第一步 | 打破惯性从底层重构 |
| steel-man | 正反论证想透后定 | 想透正反再决定 |
| socratic-questioning | 追问澄清真问题 | 说不清想问什么 |
| fact-check | 验说法真假（联网查） | 这个说法能信几分 |

## 依赖

无。纯决策/实验设计，任何环境可用。
