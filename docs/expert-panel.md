# Expert Panel — 专家会诊

## 一句话

替代"你是一位20年经验的世界级专家"。先不给方案，为问题选 3 种真正互补的专业视角，各视角独立答 4 问（重新定义问题/推荐路径/其他视角最易忽略的风险/什么新证据会改变判断），再互相质疑（共同事实/真正分歧/分歧背后的假设），最后综合输出（推荐方案/适用条件/最大风险/退出条件/第一步行动），保留未决分歧。

## 设计理念

很多问题不属于单一专业，是几个专家互相配合才能想清的。单专家视角的盲区，恰是另一个专业的常识。所以不扮一个专家，**自组一个真正互补的小型专家团，再让他们互相挑战**。

核心信念：**真正的信息都在分歧里。** 三个视角都同意的多半是常识；洞察诞生在分歧处——分歧背后是不同假设，翻出来才知道该验证什么。所以最关键的一步不是各抒己见，而是**互相质疑**。

互补是底线，同质化是失败：三个高度相似的身份等于一个视角乘三，互相质疑变成互相附和。不模仿/编造真实人物，选的是专业视角/学科/职能，不是"20年经验专家"空 persona。

## 触发方式

说以下任意一句即可触发：

- "专家会诊 / 组个专家组 / 组个专家团"
- "多视角分析 / 互补视角分析 / 不同专业视角分析"
- "让几个专家讨论一下 / 让多个视角互相质疑 / 让视角碰一碰"
- "multi-expert / 这个问题涉及多个领域帮我从不同专业角度看"

即使用户贴了涉及多领域的复杂问题说"帮我从不同角度想想"、"让几个视角碰一碰"，也应触发。

**关键区分**：多 AI 模型辩论 → model-debate；正反论证做决定 → steel-man；红队找弱点 → adversarial-review；追问澄清真问题 → socratic-questioning；互补专家组互相质疑给方案 → 本技能。

## 工作流程

### 1. 准备
提取问题/已知事实/目标/约束。信息不足只问一个最关键的问题，不问一堆。

### 2. 选 3 互补视角
每个说明为什么必要。互补测试：两个会给出相似答案就换掉一个。不选高度相似身份、不模仿真实人物、不堆"20年专家"头衔。

### 3. 各视角独立答 4 问（子 Agent 独立）
默认 3 并行子 Agent，互不见对方答案。每视角答：重新定义问题 / 推荐路径 / 其他视角最易忽略的风险 / 什么新证据改变判断。第 4 问是分化器，逼真分化。无子 Agent 降级内联扮演，更要靠第 4 问强制分化。

### 4. 互相质疑（默认一轮）
找：共同认可的事实 / 真正的分歧 / 分歧背后的不同假设。`--deep` 多轮迭代至分歧稳定或上限 3 轮。

### 5. 综合（单一方案 + 保留分歧）
给最推荐方案（单一，不和稀泥）+ 适用条件 + 最大风险 + 退出条件（挂钩反对视角的假设验证）+ 第一步行动。显式带出未决分歧。

## 力度控制

- 默认：3 子 Agent 独立 + 一轮质疑 + 单一方案保留分歧
- `--deep`：质疑多轮至分歧稳定或上限 3 轮
- `--inline`：强制内联扮演不派子 Agent
- `--quick`：2 视角 + 一轮 + 压缩输出

## 与同类技能的区分

| 技能 | 做什么 | 何时用 |
|------|--------|--------|
| **expert-panel** | 互补专家组互相质疑给方案，保留分歧 | 多领域复杂决策要专家组对撞 |
| model-debate | 多 AI 模型辩论合成共识 | 要多个不同模型的声音 |
| steel-man | 正反构建到最强后做决定 | 已有想法要正反论证 |
| adversarial-review | 红队找致命弱点 | 找漏洞把把关 |
| socratic-questioning | 追问澄清真问题 | 说不清想问什么 |

## 依赖

- 默认用子 Agent（Agent 工具）派 3 个独立视角。无子 Agent 环境降级为内联扮演。核心无外部依赖。
