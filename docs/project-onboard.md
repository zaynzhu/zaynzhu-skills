# project-onboard 使用文档

跨平台已有项目引导器。扫描一个已有代码的项目，基于文件系统证据同时生成 `CLAUDE.md` 和 `AGENTS.md` 两份可执行工程规则，让 Claude Code、Codex 等任意 agent 进入项目就能直接 vibe coding。

## 解决什么问题

内置 `init` 能为新项目生成 CLAUDE.md，但内容偏粗——只列技术栈、目录、大概怎么跑。面对一个**已有代码**的老项目，agent 缺乏足够的工程规则（怎么跑、怎么测、怎么提交、哪些别碰），没法直接 vibe coding。

`project-onboard` 解决"粗"的根因：**每条规则都有文件系统证据**，不是凭空编。证据先行，规则后写。

## 触发

- "初始化已有项目"、"给已有项目生成 claude.md"、"写 agents.md"
- "让 AI 在这个项目 vibe coding"、"项目上手初始化"
- "扫项目写规则"、"已有项目 init"、"onboard 这个项目"
- "这个项目没有 claude.md 帮我搞一个"、"让 codex 也能用这个项目"、"给老项目加 agent 规则"

边界：仅用于**已有代码**的项目。从零的新项目用内置 `init`。

## 产物

| 文件 | 说明 |
|------|------|
| `CLAUDE.md` | Claude Code 工程规则 |
| `AGENTS.md` | Codex 工程规则 |

两份内容完全一致（同一份工程规则写两遍），末尾附同步提示行。

## 11 个 section（固定顺序）

1. 项目定位
2. 技术栈
3. 目录结构
4. 开发命令
5. 测试
6. 代码约定
7. 提交规范
8. 目录约定（别碰啥）
9. 环境变量
10. 关键入口
11. 给 agent 的工作指引（核心差异点：一段话告诉 agent 开工前先读啥、改完怎么自测、怎么提交）

## 工作流程

```
Phase 1 扫描取证 → Phase 2 现有文件分析 → Phase 3 交互确认 → Phase 4 生成规则 → Phase 5 自审与同步检查
```

- **Phase 1**：按扫描 checklist 逐项取证，填进证据账本展示给用户
- **Phase 2**：若已存在 CLAUDE.md/AGENTS.md，读作证据，判断合并/重写
- **Phase 3**：确认证据账本和合并策略
- **Phase 4**：按 11 section 生成两份文件
- **Phase 5**：自审（证据可追溯、两份一致、占位符扫描）+ 写入

## 核心原则

1. **基于证据而非想象**：每条规则都能追溯到项目实际文件。查不到标"未发现"，保留 section 不删
2. **只读不跑**：只读文件系统 + 只读 git 元数据，不执行任何改变项目状态/触发构建/联网的命令
3. **两份一致**：CLAUDE.md 和 AGENTS.md 同等效力，内容一致，漂移交给 enhanced-neat-freak 收尾
4. **未发现 ≠ 不存在**：查不到也标出来，让用户知道覆盖盲区

## 源码扫描方法论（门面文件策略）

不只看配置，也理解源码结构——这是跟 init 粗版的核心差异。用"门面文件策略"有节制地全量看：

1. **骨架**：Glob 排除后目录树，限深 3 层
2. **门面文件**：每个含源码目录按优先级读 `index.*`/`__init__.py`/`mod.rs` 等门面文件（通常 re-export 公共接口，读它就懂目录职责）
3. **入口深读**：关键入口完整读，顺 import 链走一层

护栏：门面文件读全文、非门面读前 50 行、源码总读取软上限 40 个。

## 已有文件处理

- 两份都没有 → 直接生成（主场景）
- 有任一份 → 读现有内容作证据，默认合并（补缺失 section），绝不直接覆盖
- 扫到 `.cursorrules` 等其他 AI 规则文件 → 仅作线索吸收，不动它们

快路模式（"直接生成"）跳过确认，默认合并。

## 依赖

| 依赖 | 必需 | 说明 |
|------|------|------|
| Glob/Grep/Read | 必需 | 核心扫描能力，AI 内置 |
| git | 可选 | 读取 commit 风格和仓库 URL，非 git 仓库自动跳过 |

无脚本、无外部 API 调用。

## 文件结构

```
project-onboard/
├── SKILL.md                          ← 主指令文件
└── references/
    ├── scan-checklist.md             ← 扫描 checklist + 门面策略 + 证据账本格式
    ├── section-templates.md          ← 11 section 写作模板 + 示例
    └── existing-file-merge.md        ← 合并/重写规则 + 对比格式
```

## 环境兼容性

- **Claude Code**：完整支持（Glob/Grep/Read 原生）
- **Codex CLI**：完整支持（读 AGENTS.md 作为规则）
- **OpenCode / 其他**：手动复制 AGENTS.md 改名为平台对应文件即可
- 无子 agent、无浏览器、无外部脚本依赖，所有环境通用
