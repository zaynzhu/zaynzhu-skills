# project-onboard 使用文档

跨平台已有项目规则引导器。扫描已有代码仓库的文件系统证据，首次生成或持续更新根目录 `CLAUDE.md` 和 `AGENTS.md`，让 Claude Code、Codex 等 agent 快速接手项目。

## 适用场景

- 给已有项目首次生成 `CLAUDE.md`、`AGENTS.md`
- 补全或更新过期的 agent 工程规则
- 合并已有 Claude Code、Codex 规则
- 扫描老项目并提炼开发、测试、目录和入口约定

从零创建新项目时使用平台内置 init；只想讨论规则、不希望写文件时不要使用。

## 核心能力

1. **证据先行**：生成规则可追溯到 manifest、配置、源码入口、现有规则或用户确认。
2. **冲突显式化**：现有规则与当前配置冲突时展示冲突，不静默裁决。
3. **安全取证**：不运行项目命令、不联网、不读取真实 `.env` 或凭据，不查询 remote URL。
4. **高信号输出**：缺失信息留在交付报告，不让“未发现”长期占用 agent 上下文。
5. **可重复合并**：只同步受管区块，保留平台专属和自定义内容。

## 触发示例

- “初始化这个已有项目”
- “给老项目生成 CLAUDE.md 和 AGENTS.md”
- “补一下 agents.md”
- “让 Codex 能接手这个项目”
- “更新过期的 agent 规则”
- “直接扫描并生成，不用确认”

## 工作流程

```text
安全预检 → 扫描取证 → 现有规则与冲突分析 → 确认或快速默认 → 生成共享区块 → 自审与写入
```

- **安全预检**：确认目标、规则作用域和脏工作区，只授权修改根目录两份规则文件
- **扫描取证**：先发现实际生态和 workspace，再读取相关配置与关键源码
- **冲突分析**：区分强事实、强意图、弱证据和用户确认
- **生成规则**：只写有证据的 section，缺失项留在交付报告
- **自审**：检查可追溯性、区块一致性、脱敏、写入范围和幂等性

快路模式只跳过确认，不跳过已有文件读取、冲突分析或自审。

## 受管区块

两份文件只要求受管区块一致，区块外可以保留各平台专属规则：

```markdown
<!-- project-onboard:begin -->
<!-- 此区块由 project-onboard 维护；区块外可保留平台专属规则 -->

## 项目定位

...

<!-- project-onboard:end -->
```

再次运行只替换标记内部。用相同证据连续生成两次时，第二次不应产生 diff。

## 推荐规则维度

1. 项目定位
2. 技术栈
3. 目录结构
4. 开发命令
5. 测试
6. 代码约定
7. 提交规范
8. 目录约定
9. 环境变量
10. 关键入口
11. 给 agent 的工作指引

这些是推荐顺序，不是固定空骨架。没有可靠证据的 section 会被省略。

## 已有文件处理

| 情况 | 默认处理 |
|------|----------|
| 两份都没有 | 新建并写入相同共享区块 |
| 只有一份 | 保留已有内容，新建另一份 |
| 两份都有且不同 | 同步共享区块，保留区块外差异 |
| 已有受管区块 | 只更新区块内部 |
| 规则与配置冲突 | 展示冲突；快速模式保留现状并省略冲突项 |

整份重写仅在用户明确要求时执行。目标规则文件存在未提交修改时，默认使用最小合并。

## 扫描安全

- 允许读取 manifest、lockfile、CI、lint、测试和安全示例配置
- `.env.example` 等文件只提取变量名和注释
- 不读取真实 `.env`、私钥、证书、认证缓存和 keychain
- 不展示 token、密码、连接串、用户信息或 remote URL
- 不安装依赖，不执行测试、构建、格式化或项目启动命令

交付报告会明确哪些命令来自配置但没有实际执行。

## 环境兼容性

- Claude Code：使用 Glob/Grep/Read 或等价只读能力
- Codex：有 shell 时优先使用 `rg --files`、`rg -n` 和安全文件读取
- 其他 agent：使用等价的文件发现、搜索和读取能力

Skill 不依赖特定工具名、外部 API 或浏览器。
