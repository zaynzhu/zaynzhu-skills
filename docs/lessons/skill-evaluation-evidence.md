# 技能评测的证据边界与工具缺失

结论速览：先核对实际工具文件，缺少辅助脚本时可用透明聚合与静态页保留证据；两组全部通过只说明基础检查通过，不能证明技能收益。
适用条件：文本工作流技能的有／无技能对照；本次为同模型、每例一次运行，跨能力接手与真实额度收益仍待验证。

## ✅ 用逐条原始评分核对通过率，避免把满分当成提升（2026-09-22）

- **环境**：macOS 26.6.2；本轮核对使用 Python 3.9.6；原执行模型的具体版本未记录，不补写。
- **为何值得记**：完整评测使用 8 个独立子智能体会话。两组都能通过基本断言，继续按通过率打磨容易把无判别力的用例误当成效果证据。
- **最终方案**：保留每例原始回答、逐条评分与依据，先检查两组差异，再决定能作什么结论。本轮在项目根实际运行的核对命令如下：

```bash
python3 - <<'PY'
import json
from pathlib import Path
root = Path('problem-solving-workspace/iteration-1')
for mode in ('with_skill', 'without_skill'):
    files = sorted(root.glob(f'eval-*/{mode}/grading.json'))
    checks = [item for path in files for item in json.loads(path.read_text())['expectations']]
    print(f'{mode}: runs={len(files)}, passed={sum(item["passed"] for item in checks)}/{len(checks)}')
PY
```

- **验证证据**：本轮从现存评分文件重算，实际输出为：

```text
with_skill: runs=4, passed=16/16
without_skill: runs=4, passed=16/16
```

- **为什么这样做**：评分差为零并不证明技能无效，但这些断言无法证明它优于基线。单次运行无法估计稳定性，同模型对照无法证明不同能力执行者接手效果。
- **交叉验证**：8 个独立会话产出，主智能体一轮非盲评分，本轮单智能体再次核对汇总；不是 8 个审查者共同验证结论，不标“精粹”。持久证据摘要见 [评测说明](../../skills/problem-solving/evals/README.md)。
- **关键步骤**：运行前定义断言 → 两组隔离生成 → 逐条保存证据 → 核对差异和测量限制 → 收集反馈 → 决定是否迭代。完整技能维护流程见 [创建技能](../../skills/enhanced-skill-creator/SKILL.md)，不在本文件复制。
- **易错点**：本次 token 数据缺失、计时采样起点不统一，不能作额度或耗时收益比较；用户认可也不替代效果测量。
- **证据可用性**：命令依赖本地被 Git 忽略的 `problem-solving-workspace/iteration-1/`。新克隆不自带原始输出；缺失时参考持久摘要或重新评测，不能宣称已经复核原记录。

- **最终方案**：读取现有评分与数据结构约定，用工作区内的轻量脚本生成静态页，展示原始回答、评分依据及反馈入口，并明确它是替代实现。本轮已重新执行：


- **验证证据**：退出码 0，生成工作区中的 `iteration-1/review.html`；此前验证其包含 8 个反馈输入区及对应回答。文件生成和结构已验证，不宣称经过真实浏览器交互测试。

- **适用条件**：替代脚本存在且输入数据结构匹配。该脚本位于忽略目录，不是技能发布物；新环境需要恢复或重新实现，不能直接假设存在。
- **交叉验证**：单智能体生成和结构检查，本轮单智能体再次运行；用户已整体认可首版，无独立查看器审查。数据字段参考 [schemas](../../skills/enhanced-skill-creator/references/schemas.md)。

- **易错点**：静态页生成成功不等于反馈下载按钮已实测；描述优化脚本同样缺失时，应如实标记未运行，不虚构触发准确率。
