# Steel-Man — 双向钢人论证

## 一句话

在回答用户的问题或评估一个想法之前，先把正反两面都论证到最强，找到真正的分歧和关键变量，**只问一个最关键的问题**，等用户回答后再给判断。

## 设计理念

先厘清 AI 在这里的角色：**AI 不是充当钢人跟你辩论的对手，而是"执行钢人论证这个动作的人"。**

- 你的观点 = 第一个被钢人论证强化的对象
- 反对你的观点 = 第二个被钢人论证强化的对象

做完之后，AI 手里会拿到**两个钢人化后的最强版本**。靠这两个最强版本的对撞，最大程度逼近问题最本质的答案。

## 为什么需要它

人做决定时最大的陷阱不是"没想到反面"，而是**只想到一个软弱的反面**就以为自己已经客观了。软弱的反对让人更坚定原有的想法——这就是稻草人论证的害处。

钢人论证（steel-man）是稻草人的反面：把反对意见强化到它最强、最难以反驳的版本，再面对它。如果立场能在最强的反对面前站住，它才值得持有；如果站不住，越早知道越好。

本技能把这个过程做成**两轮交互**：第一轮只论证和提问，绝不给结论；第二轮才给判断。这逼着用户先想透，再下结论。

## 触发方式

说以下任意一句即可触发：

- "帮我钢人论证一下"
- "steel-man 一下这个想法"
- "双向钢人论证"
- "先别急着回答，帮我想清楚"
- "正反两面都论证一下"
- "这个想法靠谱吗 / 这个决定我拿不准"
- "论证一下我的想法"

即使用户只是说"帮我分析这个方案"、"支持反对都说说"并提供了内容，也应触发。

## 工作流程

### 第一轮：论证

1. **重述真问题** — 人经常把"嘴上问的"和"真正想解决的"混在一起。比如问要不要辞职，真正担心的可能是"再干三年还有没有竞争力"。先重述真实问题，乱七八糟的就清楚大半。挖到表面问题背后的真实诉求，表述有歧义时写出最合理的理解并标注。
2. **双向钢人论证** — 让两边都不能靠歪曲对方取胜，真正的冲突才会显露。
   - 支持方：作为最聪明的辩护者，给出最强理由（支持这件事能拿出的最好证据）
   - 反对方：作为最犀利的批评者，给出最强反击（反对这件事最难回答的质疑）
   - 双方都要真诚、有力、不注水
3. **找决定结论的关键变量** — 复杂问题看起来十几个因素，真正改变答案的往往只有一两个。预算十万还是百万，答案一定变；要短期收入还是长期品牌，答案更不一样。
   - 双方真正的分歧（定下它结论就定的底层分歧）
   - 最可能改变结论的关键变量
4. **只问一个最关键的问题** — 回答了就能最大推进决策的那一个，只问这一个。问得越多，每个问题力量越弱。

### 第二轮：判断（用户回答后）

AI 经常在最终结论上"不粘锅"，给一堆模棱两可没用的结论。所以这一轮必须逼出明确结果：
- 明确判断（支持 / 反对 / 有条件支持，不和稀泥）
- 理由（基于用户回答 + 正反论证）
- 下一步行动（具体可执行）

## 输出示例

```
## 🎯 真问题重述
> [重述用户真正想解决的问题]

## ⚔️ 双向钢人论证
### 支持方（最强论证）
- [论点]：[理由]

### 反对方（最强论证）
- [论点]：[理由]

## 🔑 真正的分歧与关键变量
**双方真正的分歧**：[底层分歧]
**最可能改变结论的关键变量**：[关键变量]

## ❓ 我需要你回答一个问题
> [只问一个最关键的问题]
```

## 力度控制

- 默认：最大诚实，正反都到最强
- `--mild`：反对方保留但语气缓和（用户已倾向某方、只想确认时）
- `--quick`：压缩篇幅，直接给关键问题（小决策）

## 与同类技能的区分

| 技能 | 做什么 | 何时用 |
|------|--------|--------|
| **steel-man** | 正反双向都构建到最强，找分歧，问一个关键问题 | 先想透正反再决定 |
| adversarial-review | 单向红队批判，找致命弱点 | 找漏洞、把把关 |
| first-principles | 还原到公理重新推导 | 打破惯性、从底层重构 |

## 依赖

无。纯思维框架，任何环境可用。
