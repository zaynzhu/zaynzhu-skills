# grilling

`grilling` 是在构建前对计划或设计进行压力测试的底层提问循环（primitive）。它逐个分支地走下决策树，一次解决一个决策之间的依赖关系，直到您和 AI 达成共识。

## 功能

- **底层核心组件**：它是 `grill-me` 和 `grill-with-docs` 背后底层的重用问答逻辑。
- **一次只问一个问题**，在收到您的回答前绝不提下一个。
- 每个问题都提供推荐的答案选项。
- 能够由代码库回答的问题会自动读取代码库，而不打扰用户。

## 依赖

- 纯 prompt 级技能，无额外脚本或 API 依赖。

## 快速开始

在支持 Skills 的工具中输入：
```bash
/grilling
```
或者在其他技能（如 triage, improve-codebase-architecture）执行过程中被 AI 自动调用。

## 决策树模型

其心智模型是一棵**决策树**：每个计划都可以分支为多个决策，而决策之间存在依赖。`grilling` 逐个节点沿树向下行进，因此前一个问题的答案会重新塑造接下来的提问方向。这也是为什么问题必须一个一个地按依赖顺序提出——并行问一堆问题会破坏这种让访谈收敛到共识的结构。

## 设计初衷

`grilling` 被设计为提问技术的**单一事实来源 (Single Source of Truth)**，作为一个由模型调用的**原子技能 (Primitive)** 抽离出来，以便每个需要进行方案对齐的技能都可以调用它，而不是重新造轮子。

虽然您通常会通过它的包装器（如无状态的 `grill-me` 或有状态的 `grill-with-docs`）来调用它，但 `improve-codebase-architecture`（改进代码库架构）等技能在评估重构决策时也会在底层依赖它。
