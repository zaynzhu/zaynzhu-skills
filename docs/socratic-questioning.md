# Socratic Questioning — 苏格拉底式提问

## 一句话

先不要给建议。通过最多 6 个问题对用户进行一次"问诊"，逐个追问、根据回答动态决定下一问，帮用户把嘴上问的和心里真正想的问题对齐，最后整理出"真正值得回答的新问题"，等用户确认后再给判断和行动建议。

## 设计理念

先厘清 AI 在这里的角色：**AI 不是回答问题的人，而是"通过提问帮用户找到真问题的人"。**

人经常嘴上问的和心里真正想表达的，不是一个意思。有人问"要不要跳槽"，心里真正担心的可能是"三年后还有没有竞争力"；有人问"这个技术选型对不对"，心里真正纠结的可能是"团队扛不扛得住维护成本"。当用户带着一团混乱的困惑来，直接给答案多半是在回答一个错误的问题。

核心信念：**回答一个错误的问题，再精彩也是浪费。**

追问还有一个隐藏价值：**帮 AI 自己补上回答所需的上下文。** 用户初始描述往往缺关键信息（事实是什么、证据从哪来、默认了哪些前提）。把这些问出来，后面给的判断才有依据。

## 为什么需要它

人带着困惑来找 AI，通常说不清自己到底在纠结什么。如果 AI 直接回答那个表面问题，用户会得到一个看似完美、其实没有解决他真实困扰的答案。苏格拉底式提问不直接回答，而是通过追问把问题本身想清楚——既帮用户理清思路，也帮 AI 补齐回答所需的上下文。

整个流程做成**两轮交互**：第一轮只追问，绝不给建议；第二轮整理出真问题，等用户确认后才给判断。

## 触发方式

说以下任意一句即可触发：

- "苏格拉底式提问"
- "苏格拉底问诊一下"
- "先别给建议，先问我"
- "帮我把问题想清楚"
- "我有点混乱，帮我理一理"
- "问诊一下 / 追问我一下"
- "我嘴上问的和心里想的不一样"
- "帮我找到真正的问题 / 我到底在纠结什么"

即使用户只是说"我有点乱"、"说不清楚自己想问什么"并提供了困惑描述，也应触发。

## 工作流程

### 第一轮：问诊（5 条纪律）

1. **一次只问一个，动态决定下一问** — 根据上一条回答决定下一问问什么，绝不提前甩出一整套问卷。最多 6 个，但信息够了立刻停，不必凑满。
2. **优先区分四类东西** — 给用户每一句打标签：可验证的事实 / 对事实的解释 / 价值判断 / 目标。不同类别追问方向不同：事实验真伪，解释找替代解释，价值判断查标准，目标看是不是真目标。
3. **逐项检查五个疑点** — 关键词是否含糊、默认了哪些前提、证据来自哪里、有没有相反解释、结论成立/不成立分别意味着什么。
4. **每次提问前用一句话说明判断更新** — `【判断更新】你刚才说 X，这让我把对问题的理解从 Y 调整成了 Z。` 这让用户看到你真的在听、在根据回答调整方向。
5. **只问可能改变结论的问题，够了就停** — 每个问题都要能通过检验：它的答案会改变我对问题的判断吗？不会就不问。

如果用户初始描述很薄，不要让他先补充——直接从模糊里挑一个最可能切中要害的点问第一个问题，靠追问把信息问出来。

### 第二轮：整理 + 判断

**2a. 整理问诊结果**（问诊停止后）：整理六项——最开始问的问题、真正想解决的问题、已确认的事实、仍未验证的假设、最可能改变结论的关键变量、一个准确具体可行动的新问题。呈现后停下，等用户确认新问题。

**2b. 给判断**（用户确认后）：判断（不和稀泥）+ 理由（扣住确认的事实和关键变量）+ 下一步行动（具体可执行）。

## 输出示例

### 每次追问

```
【判断更新】[一句话：把对问题的理解从 X 调整成 Y]

❓ [下一个问题]
```

### 整理

```
## 📋 问诊整理

1. 你最开始问的问题：[原意]
2. 你真正想解决的问题：[挖到的真实诉求，点出与第 1 项的差异]
3. 已经确认的事实：[…]
4. 仍未验证的假设：[…]
5. 最可能改变结论的关键变量：[…]
6. 真正值得回答的新问题：[一句准确具体可行动的新问题]

请你确认这个新问题对不对。确认后我再给判断和下一步。
```

## 力度控制

- 默认：最大诚实，追问到底，好奇式而非审讯式
- `--gentle`：语气更柔和（用户情绪脆弱、需引导而非追问时）
- `--quick`：压缩到 3 问内，快速收敛（小困惑时）

## 与同类技能的区分

| 技能 | 做什么 | 何时用 |
|------|--------|--------|
| **socratic-questioning** | 追问收敛，把模糊困惑整理成清晰可答的新问题 | 还没想清楚问题到底是什么、一团混乱 |
| steel-man | 正反双向构建到最强，找分歧，问一个关键问题 | 已有想法，要先想透正反再决定 |
| first-principles | 还原到公理重新推导 | 打破惯性、从底层重构 |
| adversarial-review | 单向红队批判找致命弱点 | 找漏洞、把把关 |

## 依赖

无。纯思维框架，任何环境可用。
