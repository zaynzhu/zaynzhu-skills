# adversarial-review

对抗性审查（红队审查）：像红队成员一样，对任意内容进行最尖锐的批判性审查，找出核心致命弱点，最后给出改进建议。

## 功能

- **自动识别内容类型**：代码、技术方案、商业计划、文章论述、项目计划等，自动切换审查角色
- **七维度系统审查**：逻辑漏洞、隐含假设、证据充分性、执行可行性、风险盲区、内部矛盾、遗漏关键要素
- **三级问题分级**：🔴 致命弱点（必须解决）、🟡 主要缺陷（应该解决）、🟢 改进建议
- **力度可调**：默认最大强度，支持 `--mild`、`--gentle`、`--brutal`、`--role [角色]` 参数

## 依赖

- 无需任何外部 API 或脚本依赖，纯 prompt 级技能。

## 快速开始

```bash
# 触发 adversarial-review 技能
/adversarial-review

# 或直接说
"帮我审查一下"
"这个方案有什么问题"
"红队一下"
```

## 适用场景

- 代码审查：找 bug、安全漏洞、架构问题
- 技术方案评审：暴露隐含假设和执行风险
- 商业计划书：挑战核心逻辑和市场假设
- 文章论点：检验论据充分性和推理链
- 架构设计：发现设计盲区和边界情况

## 审查力度

| 参数 | 效果 |
|------|------|
| 默认 | 最大强度，毫不留情 |
| `--mild` | 保留建设性语气，减少"致命"级别定性 |
| `--gentle` | 聚焦改进建议，减少负面表述 |
| `--brutal` | 零容忍，包含所有可能的攻击角度 |
| `--role [角色]` | 模拟特定审查者视角，如 `--role 监管机构` |
